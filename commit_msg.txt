Fix production build blocker: invalid /api rewrite kept Render on an old deploy

Root cause: rewrites() used a relative destination outside the basePath
("/api/:path*" -> "/ainos/api/:path*" with basePath:false), which is invalid
in `next build`. Every Render deploy since the AI tools were added failed at
build time, so the live site silently kept serving the oldest services page
(request forms instead of executing AI tools).

- next.config.js: rewrite destination now absolute via RENDER_EXTERNAL_URL
  (auto-set on Render), NEXTAUTH_URL fallback, localhost for dev
- turbopack.root: use __dirname (removes build warning)
- Verified: npm run build passes; all routes present incl /api/ai-tools,
  /api/ai-builder, /api/billing

This deploy brings live: AI tool execution for all 70+ services, AI Website
Builder, My Deliverables, plans & billing.
